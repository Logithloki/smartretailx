## Mandatory recapture sequence after approval

1. Capture the now-valid `/config.json`, rendered sign-in shell and PKCE request summary.
2. In a separately approved credentialed task, sign in as customer and admin; capture authenticated 200, customer 403 and admin success.
3. Only after separate application-data approval, create one controlled order with a fresh idempotency key; record redacted `orderId`, `eventId`, correlation ID and timestamps.
4. Capture order + outbox + idempotency state, publisher invocation, SQS handoff, Aurora inbox/stock/outbox and terminal order status.
5. Replay the same key, then use a different key; prove one versus two logical orders and stock deltas.
6. Connect WebSocket, capture the connections row and scoped status push; use two users if available.
7. Run k6 smoke, normal load and controlled concurrency in a safe environment/profile; save JSON summaries and matching ECS/dashboard graphs.
8. Commit/push the workflow suite, configure GitHub environments/variables/secrets/reviewers, and capture successful PR/release/promotion gates.
9. Preserve the Terraform zero-change evidence and park the environment after the live session.

Never include passwords, JWTs, authorization headers, cookies, session storage, secret values or unredacted personal data in screenshots.
